# 项目目标与验收

## 定位

这是核心能力已完成的个人电力数据采集器，不是从零开始的反爬项目，也不是多租户 SaaS。
成功标准：数据可用、异常可知、人工恢复简单、敏感会话只保存在本地。

## 保留的核心流程

1. 定时任务获取独占锁并打开专用 Chrome profile。
2. 检查会话；失效则退出 20 并调用已配置的通知接口，不反复提交密码。
3. 读取当前每日／小时图表，校验后写入 SQLite；相同日期与小时重复运行不重复插入。
4. 用户收到提示后通过人工入口续期；下一次任务正常重试。

## 本轮重构范围

- 将浏览器、解析、存储、CLI、通知、锁拆分，旧入口保留兼容层。
- 统一默认数据路径，保留数据库表结构，不迁移现有数据。
- 将旧实验抓取器移到 legacy，替换失效示例与会访问真实账户的测试。
- 覆盖跨月／跨年、空值、异常数值、幂等写入、会话失效和资源清理。
- 采集错误向上传递；拒绝把当前小时数据伪标成历史日期。

## 下一阶段：运行验收，不重写核心

| 优先级 | 工作 | 验收标准 |
| --- | --- | --- |
| P0 | 核对网页日期与小时槽位 | 与网页抽样一致；跨午夜不误归属；必要时从页面读取日期 |
| P0 | 登录／通知闭环 | 配置接收端，实测失效通知、人工续期和下一次恢复；网络异常与登录失效能区分 |
| P0 | 固定主机运行观察 | 连续 14 天记录成功、失败、空数据及人工干预；目标平均每周至多一次人工登录 |
| P1 | 数据质量与运行记录 | 记录最后成功时间与缺失日期；空数据不能被误报为完整；明确小时数据缺口不可盲目回填 |
| P1 | 备份与恢复 | SQLite 一致性备份并实际恢复一次；会话与数据备份分开管理 |
| P1 | 可复现部署 | 固定依赖版本、自动运行离线测试，验证计划任务重启及失败处理 |

这些是验收与加固任务，不意味着已有采集功能尚未完成。观察未达标时先定位会话、网络、页面变化或调度原因，不默认增加伪装手段。

## 非目标

- 绕过验证码、自动破解验证、承诺永久免登录。
- 任意历史小时回填、多账户管理、云端控制台。
- 将 Home Assistant、图形仪表盘或复杂任务队列设为核心完成前提。

## 完成定义

核心功能完成；稳定运行验收待完成。只有在实际环境验证日期正确、通知恢复闭环、备份可恢复且观察期达标后，才称为“适合个人长期运行”。不宣称零维护或通用生产平台。
